# Under the hood

This document covers how Horror Engine makes its sound, how the 3D machine is put together and how the page is built, along with the design rules the code follows.

## Design principles

- **No samples.** Every sound is synthesised live from a model of a physical object. The app never loads an audio file. The Aura and the Stinger's reverse swell reuse only the machine's own output from the last few seconds.
- **Play it like an object.** Position, pressure and speed of movement are the main controls, not note-on and note-off. A bow, a scrape or a crank makes no sound until you move.
- **One file, no install.** The page runs from a double-click (`file://`) or from any static host. Nothing needs installing and nothing loads from the network: three.js and the textures are local.
- **Local and private.** No accounts, analytics or network calls.
- **Deterministic.** All randomness comes from one seeded generator. The same starting settings, gestures and seed give the same audio, sample for sample, so a performance file can be rendered again later.
- **Kind to the audio thread.** The DSP allocates its buffers up front, or once on first use. The recorder recycles its buffers, and messages to and from the audio thread are batched.
- **Safe to listen to.** Every voice runs through a channel strip and a final look-ahead limiter. The glass voice has an ear guard on its 2–5 kHz band.

## Signal flow

```
gestures (mouse, pen, keys, MIDI, moments, loop layers, Hold)
   -> nine voices  -> channel strip (level, pan, Grit, ear guard, Distance)
                         |-> hall send ------> reverb (8-line FDN) -----------|
                         |-> spring send ----> spring tank ---------------------|
                         |-> harmonizer send -> pitch shifter (+feedback) ------|
                         |-> body send ------> wooden body + piezo ------------|
                         |-> aura capture ---> granular pad (voice VIII) ------|
                         '-> dry --------------------------------------------- +--> per-stem master
                                                                                   (tilt, volume, low cut)
                                                                                 -> look-ahead limiter
                                                                                    (about -1 dBFS) -> out
```

The recorder takes the mix after the limiter and each stem before it, all on the same frame.

## The audio engine

`src/engine.js` defines `HE_SOURCES`, the nine voice ids, and `HE_PARAMS`, the one registry of every parameter with its range, default and unit. The UI, presets and file schemas are all built from that registry.

`HECoreFactory()` returns the engine as one self-contained function. `ui.js` turns its source text into an **AudioWorklet** module, so the DSP runs off the main thread at the device's sample rate. Chrome refuses Blob-URL worklets on `file://`, so the page tries a `data:` URL first there and a Blob URL over http(s), and each falls back to the other. If AudioWorklet is missing, the same engine runs on the main thread ("compatibility mode").

The engine renders in 128-frame blocks. Per block it does the following:

1. **Moments and looper.** Scripted gestures and loop layers write into contact *slots*, the same shape as a live touch.
2. **Contacts.** Each voice takes its contacts in priority order: live touch, then moments, then loop layers (oldest first), then Hold. Voices with several instances keep each contact on its own instance.
3. **Macros.** Dread, Distance, Material and Pitch are smoothed into shared values: detune, instability, roughness, sub level, material decay and brightness, and the pitch multiplier.
4. **Voices**, each with its own model:

   | Voice | Model | Instances |
   |---|---|---|
   | E-bow string | waveguide loop with a self-oscillating magnetic driver | 2 |
   | Hurdy-gurdy | three bowed waveguide strings on a rosined wheel, six body modes | 1 |
   | Bowed metal | modal bank driven through a velocity-weakening friction contact | 3 |
   | Glass | modal bank with a stick-slip contact, wet-finger beating | 3 |
   | Struck metal | modal bank per hit | 12 voices |
   | Spring tank | three springs, each a chain of dispersive allpasses in a feedback loop | 1 |
   | Junk tray | 2D particle simulation (up to 80 pieces) driving 24 tiny resonators | 1 |
   | Aura | granular cloud over the last ~10 s of the dry bus | 32 grains |
   | Superball | stick-slip pulse train into a modal surface, with mode lock | 1 |

5. **Strip.** Each voice passes through its channel strip: level, pan, Grit, the glass ear guard and the Distance stage. The strip sends to the hall, spring, harmonizer and body, and writes the stem buffer.
6. **Shared effects:**
   - the body (twelve wooden modes and the piezo filter);
   - the harmonizer (two pairs of 70 ms read heads, with feedback);
   - the hall (an eight-line Householder feedback delay network with slowly modulated lines);
   - the reverse swell used by the Stinger.
7. **Master.** Each stem gets tilt, volume and a low cut. The sum then goes through a look-ahead limiter.

Every message from the page carries a sequence number. The engine reports the frame it applied each message on, and that log becomes the `.horror.json` performance file. `io.js` can replay a performance offline (`renderJob`) through the same engine, which is how **Render…** works.

Telemetry comes back to the page every 1024 frames: peaks per voice, limiter gain, loop positions, moment states and the junk positions for drawing.

**Speed.** In a measurement on a desktop CPU, a busy patch (eight voices held, Heartbeat and In the walls running, struck hits, harmonizer and body sends) rendered at about 7× real time on one core. That is about 0.36 ms of each 2.67 ms block at 48 kHz.

## The macros, in the engine

- **Dread:**
  - raises detune, from about 2 to 60 cents;
  - adds pitch instability and a 22–67 Hz roughness tremolo on sustained voices;
  - adds a sub-octave;
  - adds an offset to Grit;
  - bends the hurdy's fifth toward a tritone and its octave toward a minor ninth;
  - speeds up the heartbeat.
- **Distance:**
  - adds a low-pass from 20 kHz down to about 1.2 kHz;
  - drops the level by up to 15 dB;
  - narrows the image and takes away bass;
  - adds more hall, with up to 60 ms of extra pre-delay.
- **Material:** scales ring times, high-frequency loss and inharmonic stretch in the metal and glass models.
- **Pitch:** a multiplier on every voice's pitch. Below −12 st it also adds sub and lengthens the Aura's grains.

## The Machine

`machine2.js` builds the cabinet in three.js from code; there are no model files. Every playable part has an invisible **zone** with a *kind* (`play`, `bowtap`, `knock`, `puck`, `knob`, `tray`, `wand` and so on) and a handler in the `HD` table. A handler turns pointer movement into the same `{x, y, pressure}` gestures the Surface sends, and sets any parameters the part implies. For example, the slate sets Glass to Chalkboard and Chalk, and a ruler tap sets Struck to Ruler. The hint text for each part lives in `HINT`.

The textures are CC0 photo scans. `build.py` embeds them as base64 WebP, because WebGL will not load image files from `file://`. Web Workers decode them and build mip chains off the main thread. Half-size sets load first and the full-size sets stream in after.

**High detail** renders into an MSAA HDR buffer, which `look.js` finishes with bloom, ACES tone mapping, a vignette and dither (this needs WebGL 2). **Low detail** (`?quality=low`) turns off shadows and the post chain, keeps the half-size textures and renders at a pixel ratio of 1. The sound is identical in both.

The page exposes `window.__he` for scripting: state, parameters and a `ready()` check.

## File formats

- **Preset** (`.json`, `format: "horror-engine.preset"`): every parameter, the macros and a seed.
- **Performance** (`.horror.json`, `format: "horror-engine.performance"`): a preset for the starting state, plus every gesture and knob move with the frame it landed on. **Load** reads its sound, and **Render…** plays it again offline.
- **WAV:** 32-bit float or 24-bit PCM. The title, artist and credit are written into the file's INFO chunk. 24-bit stems carry a 6.02 dB pad, noted in the file.

Both JSON formats are checked against the JSON Schemas in `io.js` on load.

## Building

```
python3 build.py            # Python 3 and Pillow (pip install pillow)
```

Edit the files in `src/`, run the build and reload `index.html`. The build inlines `src/*` and the textures. `vendor/three.min.js` stays a separate file loaded by a script tag, so keep it next to `index.html`.
